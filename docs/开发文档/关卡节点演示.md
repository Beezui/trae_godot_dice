# 关卡节点演示

## 核心概念纠正

### 关键理解

根据关卡系统文档，关卡生成遵循以下逻辑：

1. **核心节点**：仅包含**战斗关卡（类型 1）**和**奇遇关卡（类型 2）**
2. **随机节点**：包含所有 4 种类型（战斗、奇遇、交易、奖励）
3. **生成顺序**：
   - 步骤 1：确定总关卡数（总量控制，如 10 个）
   - 步骤 2：生成核心节点骨架（仅战斗 + 奇遇）
   - 步骤 3：在核心节点之间插入随机节点，达到总量控制要求

### 核心节点 vs 随机节点

| 特性 | 核心节点 | 随机节点 |
|------|----------|----------|
| 类型 | 仅战斗、奇遇 | 战斗、奇遇、交易、奖励 |
| 入口/出口 | 可有多个入口和出口 | 仅 1 个入口和 1 个出口 |
| 作用 | 构成网状结构骨架，提供路径分支 | 填充路径长度，达到总量控制 |
| 位置 | 关键节点位置 | 核心节点之间 |

### 设定条件

- **总量控制**：10 个关卡（难度 1）
- **核心节点骨架**：1 → 2 → 3（3 个核心节点）
- **需要插入的随机节点数**：10 - 3 = 7 个随机节点

### 生成步骤

#### 步骤 1：生成核心节点骨架

```
核心节点路径：1(初始·奇遇) → 2(战斗) → 3(终点·战斗)

层级结构:
层级 1: 核心节点 -1(初始)
         │
         ▼
层级 2: 核心节点 -2(中转)
         │
         ▼
层级 3: 核心节点 -3(终点)
```

**在节点 1 和节点 2 之间插入 3 个随机节点：**

```

    │         ▼
```

## 路径验证

### 验证规则检查

✅ **每条路径包含初始核心节点和终局节点**
- 路径 1: 1(初始) → ... → 3(终点) ✓
- 路径 2: 1(初始) → ... → 5(终点) ✓
- 路径 3: 1(初始) → ... → 3(终点) ✓

✅ **每条路径不包含循环路径**
- 所有节点都是单向前进，无回头路 ✓

✅ **核心节点出口规则**
- 核心节点必须有至少一个入口或出口大于 1
- 节点 1: 2 个出口 (2, 4) ✓
- 节点 2: 2 个出口 (3, 5) ✓
- 节点 4: 2 个出口 (3, 5) ✓
- 节点 3、5: 0 个出口 (终点) ✓

✅ **随机节点规则**
- 每个随机节点只有 1 个入口和 1 个出口 ✓
- 随机节点分布在核心节点之间 ✓
- 避免连续出现多个奖励节点或交易节点 ✓

✅ **总量控制**
- 路径总关卡数应在目标值（如 10 个）的±10% 范围内
- 示例路径：7 个核心节点 + 随机节点，可根据需要调整

## 总结

根据对关卡系统文档的重新理解，关键要点如下：

### 核心概念

1. **核心节点**：仅包含战斗（类型 1）和奇遇（类型 2），构成网状结构的骨架
2. **随机节点**：包含所有 4 种类型（战斗、奇遇、交易、奖励），插入在核心节点之间
3. **生成顺序**：总量控制 → 核心节点骨架 → 插入随机节点
