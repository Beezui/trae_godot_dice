# 关卡系统

## 简介

- 管理游戏之内关卡切换
- 管理各个关卡配置，包括地图、敌人、npc、产出资源等
- 由每个关卡对应一个场景，但一个场景可用于多个关卡
- 游戏内所有活动均在关卡中进行
- 关卡内必定可进行投掷
- 关卡内至少包含一名非玩家角色

## 场景配置

  - 我们需要预创建多个场景，生成关卡时直接使用这些场景，再加入关卡内的元素，如敌人、npc 及特殊道具等，相关场景配置表如下，相应文件 scenes.json
  ```
    |id| name | path |
    | --- | --- | --- | 
    |1| 场景 1| 场景 1| 
    |2| 场景 2| 场景 2| 
    | ... | ... | ... |
  ```
  - 表头解释：
     - id：场景 id，用于唯一标识一个场景
     - name：场景名称，用于在游戏内显示
     - path：场景路径，用于在游戏内加载场景，默认路径为 `res://scenes/游戏场景/`,默认文件名格式为 `场景路径.tscn`
 
  - 创建说明
     - 创建场景时碰撞相关设置参考 sandbox_template.md，
     - 相关镜头管理请参考 CameraManager 相关文档，遵循统一管理
     - 可见墙体等暂时无需配置，后续会根据需要使用相关美术资源

## 关卡分类

游戏内关卡可分为以下几类
    - 1.战斗关卡
    - 2.奇遇关卡
    - 3.交易关卡
    - 4.奖励关卡

 ### 战斗关卡

    - 游戏的所有战斗皆在战斗关卡内进行
    - 战斗关卡内必定包含至少一个敌人
    - 战斗关卡内可包含不同数量的中立 npc

 ### 奇遇关卡

    - 游戏的所有奇遇皆在奇遇关卡内进行
    - 奇遇关卡内必定包含至少一个 npc
    - 奇遇关卡内可包含不同数量的中立 npc

 ### 交易关卡
   
    - 游戏的所有交易皆在交易关卡内进行
    - 交易关卡内必定包含至少一个 npc
    - 包含多种物品、技能等交易选项

 ### 奖励关卡
   
    - 游戏的所有奖励皆在奖励关卡内进行
    - 奖励关卡内必定包含至少一个奖励
    - 奖励关卡内可包含不同数量的奖励

## 生成逻辑（已实现）

  游戏内关卡按照以下规则生成，当前已完成全部核心算法实现：

   - ✅ 网状结构生成
   - ✅ 阶段性终局
   - ✅ 网状层级生成
   - ✅ 路径生成（随机偏移区间分配算法）
   - ✅ 随机节点类型确认
   - ✅ 路径验证

   ### 核心文件结构
   
   ```
   scripts/levels/
   ├── level_generator.gd              # 关卡生成器主控制器
   ├── level_generator_core.gd         # 核心生成算法（ Boss 节点、连接算法）
   ├── level_generator_random.gd       # 随机节点生成器
   ├── level_data.gd                   # 关卡数据容器
   └── level_validator.gd              # 路径验证器
   
   scripts/ui/
   └── level_map_display.gd            # 关卡地图可视化显示
   
   config/
   ├── level_generation_config.json    # 生成配置参数
   ├── boss.json                       # Boss 配置
   └── random_nodes.json               # 随机节点配置
   ```

   ### 网状结构

   - 游戏内所有关卡按网状结构连接，每个关卡可能包含多个入口和出口
   - 每局生成的网状结构应保证玩家在经历各种选择后，能够经历不同的关卡，保持游戏的趣味性和挑战性
   - 每层网状结构节点数保证一定随机性，总层数在 15-20 层之间

   ### 阶段性终局
   
   - ✅ 已实现 3-4 个阶段，每个阶段有 Boss
   - ✅ 每个阶段 15-20 层
   - ✅ Boss 节点 layer 值动态计算（本阶段最后一层）
   - ✅ 阶段间通过 Boss 节点连接（前阶段 Boss → 本阶段第 1 层）
   - ✅ Boss 配置在 boss.json 中：
   
   |id| name |difficulty| level |weight|hero_id|scene_id|
   | --- | --- | --- | --- | --- | --- | --- | --- |
   
   - id: 终局 boss id，用于唯一标识一个终局 boss
   - name: 终局 boss 名称，用于在游戏内显示
   - difficulty: 该 boss 允许在游戏难度大于等于 difficulty 时生成
   - level: 阶段数，该 boss 允许在第 level 阶段生成
   - weight: 终局 boss 权重，可生成时根据权重随机选择 boss
   - hero_id: boss 使用的角色 id，读取 hero.json 中的 id 配置
   - scene_id: 终局 boss 所属的场景 id，用于在游戏内显示，读取 scene.json 中的 id 配置

   ### 网状层级生成
   
   - ✅ 确认终局节点后，在每个阶段的终局节点和初始节点之前划分网状层级
   - ✅ 每层网状结构节点数在 2-6 之间
   - ✅ 每个阶段的总层级在 15-20 层之间
   - ✅ 使用全局层级计数器（global_layer_counter）确保层级连续性

   ### 路径生成（随机偏移区间分配算法）
   
   - ✅ 从第一层开始，将每个节点与下一层的节点连接
   - ✅ 使用**随机偏移区间分配算法**，在保证不交叉的前提下增加随机性
   - ✅ 核心特性：
     - 每个 from_node 连接连续的 to_node 区间
     - 区间之间不重叠（避免交叉）
     - 添加随机偏移（0 到 total_to/3），打破对称性
     - 10% 概率跳过某些连接，让路径更自然
     - 每个 to_node 最多被 2 个 from_node 连接
   - ✅ 允许出现跨层级连线，但最多跨越 1 层（当前已禁用，因随机选择会破坏顺序）
   - ✅ 最后一层的所有节点都必须连接到终局节点上
   - ✅ 阶段间连接：前阶段 Boss 连接到本阶段所有第 1 层节点

   ### 随机节点类型确认
  
   - ✅ 为节点赋予类型（战斗、奇遇、交易、奖励）
   - ✅ 节点权重配置 random_nodes.json：
   
   |id| name | type |weight|des|npc|scene|
   | ... | ... | ... | ... | ... | ... | ... |
   
   表头解释：
    - id：随机节点 id，用于唯一标识一个随机节点
    - name：随机节点名称，用于在游戏内显示
    - type：随机节点类型，1 为战斗关卡，2 为奇遇关卡，3 为交易关卡，4 为奖励关卡
    - weight：随机节点权重，用于在生成随机节点时，根据权重随机选择节点
    - des：随机节点描述，用于在游戏内显示
    - npc：随机节点内包含的 npc，用于在奇遇关卡内生成，读取 hero.json 中的 id 配置，多个 npc 之间用分号隔开，空字符串表示无 npc
    - scene：随机节点所属的场景，用于在游戏内显示，读取 scene.json 中的 id 配置
   
   ### 验证路径
   
   - ✅ 验证所有路径是否合法
   - ✅ 验证规则：
     - 每条路径必须包含终局节点
     - 每条路径不能包含循环路径，不可有回头路
     - 每条路径总节点数在 15-20 之间，允许有 10% 的浮动
     - 每个阶段路径必须收敛到每个阶段的终局节点
     - 无同层连接（已通过算法保证）
   - ✅ 每条路径验证通过后，即可认为该路径合法

## 可视化显示

### 节点显示规则

- ✅ 使用唯一 ID 显示（节点#1, 节点#2...）便于调试
- ✅ 按节点 ID 排序，确保从上到下的顺序一致
- ✅ 不同节点类型使用不同颜色：
  - 战斗：红色 (#FF4D4D)
  - 奇遇：蓝色 (#4D94FF)
  - 交易：黄色 (#FFF04D)
  - 奖励：绿色 (#4DFF80)
- ✅ 核心节点（Boss、起点、终点）使用粗边框
- ✅ 随机节点使用细边框

### 连线规则

- ✅ 白色连线，带箭头指示方向
- ✅ 严格按顺序连接，避免交叉
- ✅ 支持多对一、一对多连接

## 配置参数

### level_generation_config.json

```json
{
  "generation": {
    "min_stages": 3,          // 最少阶段数
    "max_stages": 4,          // 最多阶段数
    "layers_per_stage_min": 15,  // 每阶段最少层数
    "layers_per_stage_max": 20,  // 每阶段最多层数
    "nodes_per_layer_min": 2,    // 每层最少节点数
    "nodes_per_layer_max": 6     // 每层最多节点数
  },
  "visual": {
    "node_radius": 35.0,      // 节点半径
    "node_spacing_x": 200.0,  // 节点水平间距
    "node_spacing_y": 150.0,  // 节点垂直间距
    "layer_padding": 100.0    // 层级间距
  }
}
```

## 使用说明

### 快速测试

1. 打开 Godot 项目
2. 运行 `res://scenes/test/LevelMapTest.tscn` 场景
3. 系统会自动生成关卡并显示
4. 点击"重新生成"按钮可重新生成关卡
5. 点击"打印日志"按钮可在控制台查看详细生成信息

### 日志输出

生成过程会输出详细日志，包括：
- 每层的节点数量和 ID
- 每个节点的连接目标
- 所有节点的 layer 值
- 总连接数
- 验证结果

### 调试技巧

- 查看 `log/log.txt` 文件获取完整日志
- 关注"同层连接"错误（应始终为 0）
- 检查 Boss 节点的 layer 值是否正确（应为本阶段最后一层）
- 验证阶段间连接日志（"前阶段 Boss 连接到本阶段第 X 层"）

## 已知限制

- 跨层级连接已禁用（因随机选择会破坏顺序导致交叉）
- 节点位置按 ID 严格排序，可能需要视觉优化
- 连接算法保证不交叉，但可能存在视觉上的汇聚（多个 from 连接到一个 to）
