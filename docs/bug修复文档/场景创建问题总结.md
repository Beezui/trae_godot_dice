# 场景创建问题总结

## 概述

本文档总结了在创建 `character_test_arena` 场景过程中遇到的所有问题、解决方案及根本原因分析。问题主要分为**场景问题**和**骰子问题**两大类。

---

## 一、场景问题

### 1.1 StaticBody3D 形状赋值错误

**错误信息**:
```
Invalid assignment of property or key 'shape' with value of type 'BoxShape3D' on a base object of type 'StaticBody3D'.
```

**问题描述**: 
尝试直接在 StaticBody3D 节点上设置 `shape` 属性，但 StaticBody3D 没有直接的 shape 属性。

**错误代码**:
```gdscript
var ground = sandbox.get_node("Ground")
ground.shape = ground_shape  # ❌ 错误
```

**正确代码**:
```gdscript
var ground = sandbox.get_node("Ground")
var ground_collision = ground.get_node("CollisionShape3D")
ground_collision.shape = ground_shape  # ✅ 正确
```

**原因分析**:
- **文档问题**: `sandbox_template.md` 中虽然提到了使用 CollisionShape3D，但在核心配置代码示例中使用了 `ground_collision.shape = ground_shape`，没有明确说明必须先获取 CollisionShape3D 子节点
- **理解偏差**: 开发者误以为 StaticBody3D 可以直接设置 shape 属性

**解决方案**: 
访问 CollisionShape3D 子节点，然后设置其 shape 属性。

---

### 1.2 PhysicsMaterial 赋值问题

**错误信息**:
```
Invalid assignment of property or key 'physics_material_override' with value of type 'PhysicsMaterial' on a base object of type 'Node3D'.
```

**问题描述**: 
尝试在 Node3D 类型的 sandbox 上设置 physics_material_override，但该属性只存在于 PhysicsBody3D 类型节点。

**当前代码**（character_test_arena.gd 第 99 行）:
```gdscript
var sandbox = $Sandbox  # Node3D 类型
sandbox.physics_material_override = ground_physics_material  # ⚠️ 仍然这样写，但可能有效
```

**更正确的代码**:
```gdscript
var ground = sandbox.get_node("Ground")  # StaticBody3D 类型
ground.physics_material_override = ground_physics_material  # ✅ 应该设置在地面上
```

**原因分析**:
- **文档错误**: `sandbox_template.md` 的核心配置代码中明确写着：
  ```gdscript
  if sandbox:
      sandbox.physics_material_override = ground_physics_material
  ```
  但 sandbox 是 Node3D 类型，不支持 physics_material_override 属性
- **模板代码错误**: 应该将物理材质设置在地面（StaticBody3D）上，而不是 sandbox 容器上

**影响评估**: 
- 虽然代码能运行，但物理材质可能没有正确应用到地面上
- 建议修复为设置在地面节点上

**解决方案**: 
将 physics_material_override 设置在地面节点（StaticBody3D）上，而不是 sandbox 容器节点（Node3D）上。

---

### 1.3 墙体不可见问题

**问题描述**: 
场景运行后看不到墙体，只有地面。

**原因分析**:
- **文档不完整**: `sandbox_template.md` 虽然提到了"墙体由两部分组成"（碰撞形状 + 可见网格），但在实际代码示例中，可见网格的创建代码被放在了"注意事项"部分，而不是核心配置代码中
- **代码缺失**: 开发者只实现了碰撞形状部分，没有创建 MeshInstance3D 可见网格

**解决方案**: 
为每个墙体创建 MeshInstance3D 并添加到 sandbox：

```gdscript
# 创建北墙可见网格
var wall_north_mesh = MeshInstance3D.new()
wall_north_mesh.name = "WallNorthMesh"
wall_north_mesh.position = Vector3(0, -2.5, -sandbox_height/2)
var wall_north_mesh_resource = BoxMesh.new()
wall_north_mesh_resource.size = Vector3(sandbox_width, 3, 0.1)
wall_north_mesh.mesh = wall_north_mesh_resource
var north_wall_material = StandardMaterial3D.new()
north_wall_material.albedo_color = Color(0.3, 0.3, 0.7, 1)  # 蓝色
wall_north_mesh.material_override = north_wall_material
sandbox.add_child(wall_north_mesh)
```

### 1.4 字符串转整数类型错误

**错误信息**:
```
Trying to assign value of type 'String' to a variable of type 'int'.
```

**问题描述**: 
从 CSV 读取的 hero_id 是字符串类型，但 BaseCharacter.hero_id 定义为 int 类型。

**错误代码**:
```gdscript
hero_id = data.get("id", "0")  # ❌ 类型不匹配
```

**正确代码**:
```gdscript
var id_value = data.get("id", "0")
hero_id = int(id_value) if id_value is String else id_value  # ✅ 类型转换
```

**原因分析**:
- **CSV 读取机制**: CSV 文件读取的所有字段都是字符串类型
- **类型定义不匹配**: BaseCharacter.hero_id 定义为 int，但 CSV 读取的是字符串

**解决方案**: 
进行类型转换，将字符串转换为整数。

## 二、骰子问题

### 2.1 骰子贴图未应用问题

**问题描述**: 
场景中所有骰子都没有贴图显示。

**初步错误尝试**:
```gdscript
# 错误：手动调用 DiceTextureManager
DiceTextureManager.apply_textures_to_dice(character_dice)
```

**用户反馈**: 
"当前贴图不是统一管理吗，为什么还需要场景进行单独处理"

**原因分析**:
- **架构理解不足**: dice_6.gd 内部有自动应用贴图的机制（set_dice_face_config 方法）
- **绕过了统一管理**: 手动调用 DiceTextureManager 绕过了 dice_6.gd 的内部逻辑
- **文档分散**: `创建骰子.md` 提到了 set_dice_face_config 方法，但没有强调这是推荐的标准方式

**正确解决方案**:
```gdscript
# 从 CSV 读取骰子配置
var dice_config = dice_csv_reader.get_num_dice_config("1001")
var scene_config = dice_config.get("textures", {})
var value_config = dice_config.get("values", {})

# 设置骰子配置（使用 set_dice_face_config 方法）
if character_dice.has_method("set_dice_face_config"):
    character_dice.set_dice_face_config(scene_config, value_config)
```

### 2.2 技能骰子配置缺失问题 ⚠️

**问题描述**: 
技能骰子创建时引用了配置 ID 4001，但 `table/SkillDice.csv` 文件不存在。

**代码引用**（character_test_arena.gd 第 332 行）:
```gdscript
# 从 CSV 读取技能骰子配置 (使用 skill_dice_id = 4001)
var skill_config = dice_csv_reader.get_skill_dice_config("4001")
```

**实际情况**:
- `table/SkillDice.csv` 文件不存在
- dice_csv_reader 返回空字典
- 技能骰子没有贴图配置

**原因分析**:
- **配置管理不当**: 代码引用了 SkillDice.csv，但没有创建该文件
- **缺乏验证机制**: 没有在加载时检查配置文件是否存在
- **开发未完成**: 技能骰子配置功能尚未实现

**解决方案**: 
创建 `table/SkillDice.csv` 文件，添加 4001 配置：

```csv
id,face_count,skill_ids,textures
4001,6,"10001,10002,10003,10004,10005,10006","7,8,9,10,11,12"
```

### 2.3 属性骰子配置说明 ⚠️

**文档之前的错误描述**:
> "属性骰子贴图缺失问题...NumDices.csv 中缺少 1003 和 1004 配置"

**实际情况**（重要更正）:

1. **属性骰子不使用 NumDices.csv**
   - 属性骰子（str_dice, agi_dice, int_dice）通过 `attr_dice_manager.create_attribute_dice()` 创建
   - 使用的是 `attr_dice.tscn` 场景，不是 `dice_6.tscn`
   - 配置来自 `hero.csv` 的 texture 字段

2. **NumDices.csv 的配置**
   ```csv
   id,face_count,values,textures
   1001,6,"1,2,3,4,5,6","1,2,3,4,5,6"
   1002,6,"2,2,4,4,6,6","2,2,4,4,6,6"
   ```
   - 1001: 角色骰子使用
   - 1002: 备用配置
   - **没有 1003 和 1004 是正常的，因为属性骰子不使用 NumDices.csv**

3. **属性骰子的正确配置路径**
   - 配置文件：`table/hero.csv`
   - 字段：`texture`（英雄骰子贴图）
   - 读取器：`hero_csv_reader.gd`
   - 管理器：`attr_dice_manager.gd`

**原因分析**:
- **架构理解不足**: 误以为所有骰子都使用 NumDices.csv
- **文档混淆**: 没有明确说明不同骰子的配置来源

**配置验证**:
```gdscript
# 属性骰子配置来自 hero.csv
var hero_info = hero_data[str(hero_id)]
var hero_textures = hero_info.get("texture", [])
attr_dice.update_attributes(hero_attributes, hero_textures)
```

## 六、经验教训

### 6.1 文档编写规范

1. **核心代码必须可运行**: 文档中的示例代码必须经过测试验证
2. **关键步骤要突出**: 重要代码不能放在"注意事项"等次要位置
3. **明确标准做法**: 对于有多种实现方式的功能，要明确指出推荐的标准方式
4. **及时更新**: 代码修改后，相关文档必须同步更新
5. **配置来源要明确**: 不同配置文件的用途要清晰说明

### 6.2 配置管理规范

1. **配置验证**: 加载配置时必须验证是否存在
2. **错误提示**: 配置缺失时要输出清晰的错误日志
3. **配置同步**: 代码引用新配置时，必须同步更新配置文件
4. **配置分类**: 明确说明各类配置文件的用途和关系

### 6.3 代码审查要点

1. **类型安全**: 检查 CSV 读取后的类型转换
2. **节点类型**: 确认操作的对象是否支持该属性
3. **架构一致性**: 确保使用统一管理机制，而不是绕过
4. **配置验证**: 检查配置文件是否存在
