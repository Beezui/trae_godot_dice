# 骰子系统重构计划 (v2.0)

## 核心理念

**统一化 + 模块化 + 配置驱动**

1. **统一投掷逻辑** - 所有场景使用相同的投掷控制器，保证手感一致
2. **统一结果检测** - 所有骰子使用相同的检测算法
3. **策略模式贴图映射** - 通过骰子类型选择不同的贴图策略
4. **清理无效场景** - 仅保留核心场景，删除测试场景

### ⚠️ 重要说明：重构范围

**完全保留的核心功能**:
1. ✅ **技能系统架构** - SkillManager、具体技能实现完全保留
2. ✅ **骰子物理参数** - 质量、阻尼、反弹系数等保持现有值

**重构范围**:

### 目标 2: 统一骰子投掷方法

**当前问题**: 
- dice_demo_script.gd 和 skill_dice_test.gd 各有投掷逻辑
- 参数分散，难以调优
- 代码重复

**解决方案**: 创建统一的投掷控制器 `DiceThrowController`

**核心特性**:
- 封装所有投掷相关逻辑
- 提供统一的投掷接口
- 支持蓄力投掷、普通投掷
- 支持震动效果
- 支持抛物线运动
- 全局单例模式 (Autoload)

**核心 API**:
```gdscript
# 投掷控制器 (Autoload)
class_name DiceThrowController
extends Node

# 配置参数 (可在项目设置中配置)
var max_charge_time: float = 2.0
var max_force: float = 20.0
var min_force_ratio: float = 0.3
var shake_amplitude: float = 0.05
var shake_frequency_base: float = 15.0

# 投掷接口
func throw_with_charge(dices: Array, charge_ratio: float, start_positions: Dictionary)
func throw_normal(dices: Array, force_multiplier: float = 1.0)
func apply_shake(dices: Array, original_positions: Dictionary, charge_ratio: float, delta: float)
func reset()

# 使用示例 (在场景中)
func _input(event):
    if event.is_action_pressed("ui_accept"):
        DiceThrowController.start_charge()
    elif event.is_action_released("ui_accept"):
        DiceThrowController.throw_with_charge(get_all_dices(), DiceThrowController.get_charge_ratio())
```

### 目标 3: 统一结果检测方式

**当前问题**: 
- dice_6.gd 和 attr_dice.gd 都有 check_dice_value() 实现
- 都使用向量点积法，但实现细节不同
- 日志格式不统一

**解决方案**: 创建统一的结果检测器 `DiceResultDetector` (Autoload)

**核心特性**:
- 统一的向量点积法实现
- 统一的日志输出格式
- 支持批量检测
- 支持稳定性检测
- 全局单例模式 (Autoload)

**核心 API**:
```gdscript
# 结果检测器 (Autoload)
class_name DiceResultDetector
extends Node

# 检测接口
func check_dice_value(dice: RigidBody3D) -> int
func check_all_dice(dices: Array) -> Dictionary
func wait_for_dice_stable(dices: Array, timeout: float = 5.0) -> bool
func get_face_index(dice: RigidBody3D) -> int

# 使用示例
func check_results():
    var dices = get_all_dices()
    var results = DiceResultDetector.check_all_dice(dices)
    print("骰子结果：", results)
```

### 目标 4: 贴图映射策略化 (重要)

**当前问题**: 
- dice_6.gd 和 attr_dice.gd 的贴图逻辑分散
- 未来可能有更多骰子类型 (技能骰子、元素骰子等)
- 代码重复，难以维护

**解决方案**: 使用**策略模式**整合贴图逻辑

**架构设计**:

```gdscript
# 骰子基类 (所有骰子继承)
class_name BaseDice
extends RigidBody3D

# 骰子类型枚举
enum DiceType { NUM, ATTR, SKILL, ELEMENT }
var dice_type: DiceType

# 贴图策略接口
class DiceTextureStrategy:
    func apply_textures(mesh_instance: MeshInstance3D, config: Dictionary) -> void:
        pass

# 数字骰子贴图策略
class NumDiceStrategy:
    func apply_textures(mesh, config):
        # 加载数字贴图 (dice_face_1.png 等)
        # 应用到 6 个面
        pass

# 属性骰子贴图策略 (保留现有 SubViewport 动态纹理)
class AttrDiceStrategy:
    func apply_textures(mesh, config):
        # 加载英雄贴图
        # 创建 SubViewport 生成动态纹理
        # 添加属性数值文字
        # 应用到 6 个面
        pass

# 技能骰子贴图策略
class SkillDiceStrategy:
    func apply_textures(mesh, config):
        # 加载技能图标
        # 应用到 6 个面
        pass

# 贴图管理器
class DiceTextureManager:
    var strategies = {}
    
    func register_strategy(type: DiceType, strategy: DiceTextureStrategy):
        strategies[type] = strategy
    
    func apply_textures(dice: BaseDice, config: Dictionary):
        var strategy = strategies.get(dice.dice_type)
        if strategy:
            strategy.apply_textures(dice.$MeshInstance3D, config)
```

**使用方式**:

```gdscript
# 在 BaseDice._ready() 中
func _ready():
    var texture_manager = DiceTextureManager.get_instance()
    var config = get_dice_config()  # 从 CSV 或配置读取
    texture_manager.apply_textures(self, config)

# 在场景中使用
extends Node3D

func create_dice(dice_type: BaseDice.DiceType, position: Vector3):
    var dice = dice_scene.instantiate()
    dice.dice_type = dice_type
    dice.position = position
    add_child(dice)
    return dice

# 创建数字骰子
var num_dice = create_dice(BaseDice.DiceType.NUM, Vector3(0, 4, 6))

# 创建属性骰子
var attr_dice = create_dice(BaseDice.DiceType.ATTR, Vector3(-2, 4, 6))
attr_dice.attr_type = "str"
attr_dice.hero_id = 1
```

**优势**:
1. ✅ **代码复用** - 贴图逻辑集中在策略类中
2. ✅ **易于扩展** - 新增骰子类型只需添加新策略
3. ✅ **类型安全** - 通过 DiceType 枚举确保正确性
4. ✅ **配置驱动** - 通过配置决定贴图内容
5. ✅ **保留特色** - 属性骰子的 SubViewport 动态纹理完全保留

### 目标 5: 场景解耦

1. **依赖注入**: 通过参数传递依赖，而非硬编码

3. **接口抽象**: 定义标准接口，场景通过接口交互

**解耦策略**:
- 核心场景不直接引用其他核心场景
- 通过 SkillManager 等 Autoload 单例进行通信
- 使用信号系统传递事件
- 配置文件驱动场景行为

### Godot 坐标系说明
**必须严格遵守**sandbox_template.md 中的坐标系定义:
- x 轴：水平方向，向右为正
- y 轴：垂直方向，向上为正
- z 轴：前后方向，向前为正
- 屏幕上方：z 轴负方向
- 屏幕下方：z 轴正方向
- 屏幕左侧：x 轴负方向
- 屏幕右侧：x 轴正方向

- 角阻尼：0.03
