# 技能系统重构计划

## 当前问题分析

### 现有架构问题
1. **技能逻辑分散**：技能效果代码分散在各个测试场景中（如 `fireball_skill_test.gd`、`skill_dice_test.gd`）
2. **场景依赖严重**：技能释放依赖特定场景的节点（如 `target_dice1`、`attacker_dice` 等）
3. **无法独立运行**：技能代码无法脱离测试场景独立使用
4. **缺乏统一接口**：没有统一的技能调用接口，各场景自行实现

## 目标架构设计

### 核心原则
1. **技能独立性**：所有技能代码独立存放，不依赖任何场景
2. **参数化设计**：技能释放所需参数（目标、施法者等）通过参数传递
3. **统一接口**：提供统一的技能调用接口，任何场景都可通过技能 ID 调用
4. **配置驱动**：技能行为完全由 `skill.json` 配置驱动

## 技能调用接口设计

### SkillManager 接口
```gdscript
# 调用技能
# 参数：
#   skill_id: 技能 ID
#   caster: 施法者节点（可选）
#   targets: 目标数组（可选）
#   params: 额外参数（可选，包含骰子结果等）
func use_skill(skill_id: String, caster: Node = null, targets: Array = [], params: Dictionary = {}) -> bool

# 注册技能
func register_skill(skill_id: String, skill_instance: SkillBase)

# 获取技能实例
func get_skill(skill_id: String) -> SkillBase
```

### SkillBase 接口
```gdscript
# 执行技能
# 参数：
#   caster: 施法者节点
#   targets: 目标数组
#   params: 额外参数（骰子结果、技能配置等）
func execute(caster: Node, targets: Array, params: Dictionary)

# 清理技能效果
func cleanup()

# 获取技能配置
func get_config() -> Dictionary
```

## 测试流程

1. **单元测试**：在 `skill_test_arena` 中测试单个技能
2. **集成测试**：在 `skill_dice_test` 中测试技能骰子 + 属性骰子组合
3. **场景测试**：确保技能在不同场景中都能正常工作

## 注意事项

1. **场景无关性**：技能代码不能硬编码引用任何场景节点
2. **参数完整性**：所有需要的数据都通过 `execute()` 参数传递
3. **资源管理**：技能创建的临时对象需要正确清理
4. **错误处理**：处理目标不存在、配置缺失等异常情况
5. **性能优化**：技能对象池、资源复用等
