# 关卡场景创建计划（重构版）

## 📋 任务概述

根据关卡系统文档要求，创建三个标准化的 3D 关卡场景模板，用于后续关卡系统开发。

**重要架构调整**：
- 当前使用四面墙 + 地面作为测试和碰撞边界
- 未来将替换为完整的美术场景资源（如导入的城镇模型）
- 碰撞边界保持独立配置，不依赖美术资源
- 摄像机和投掷逻辑保持统一管理

## 🎯 目标

1. 创建一个**可替换美术资源**的标准化场景模板
2. 基于模板创建三个场景：神秘商店、熔火之窟、村庄
3. 所有场景遵循 sandbox_template.md 的配置规范
4. 使用 CameraManager 统一管理摄像机
5. 使用 DiceThrowController 统一骰子投掷逻辑
6. **碰撞边界与可见墙体分离**，便于后续替换

## 📐 场景规格

### 基本信息
- **场景类型**: 3D 场景（Node3D 根节点）
- **场景尺寸**: 24.0 x 13.5（16:9 比例，放大 1.5 倍）
- **地面位置**: y = -4
- **墙壁高度**: 碰撞 50，可见 3

### 摄像机配置（CameraManager 统一管理）
- **位置**: Vector3(1.3, 50, 14.1)
- **FOV**: 15.0 度
- **旋转**: Vector3(-75 * PI/180, 5.1 * PI/180, -4.9 * PI/180)
- **预设**: default, high, low, wide

### 光照设置
- **类型**: DirectionalLight3D
- **位置**: (10, 10, 10)
- **旋转**: Transform3D(0.7071, 0.5, 0.5, 0, 0.7071, -0.7071, -0.7071, 0.5, 0.5)

### 墙壁颜色规范
- **北墙（屏幕上方）**: 蓝色 (0.3, 0.3, 0.7, 1)
- **南墙（屏幕下方）**: 红色 (0.7, 0.3, 0.3, 1)
- **东墙（屏幕右侧）**: 黄色 (0.7, 0.7, 0.3, 1)
- **西墙（屏幕左侧）**: 绿色 (0.3, 0.7, 0.3, 1)

### 骰子投掷区域
- **位置**: 屏幕下方，靠近南墙
- **z 坐标**: 4.75（sandbox_height/2 - 2）
- **y 坐标**: 4（悬浮高度）
- **x 坐标**: 居中或根据骰子数量自动计算

## 🏗️ 场景节点结构（双层架构设计）

### 当前实现（测试阶段）
```
Node3D (主节点)
├── Camera3D (摄像机，由 CameraManager 管理)
├── DirectionalLight3D (光源)
├── BoundarySystem (StaticBody3D) - 碰撞边界系统（必须保留）
│   ├── Ground (CollisionShape3D) - 地面碰撞
│   ├── WallNorth (CollisionShape3D) - 北墙碰撞
│   ├── WallSouth (CollisionShape3D) - 南墙碰撞
│   ├── WallEast (CollisionShape3D) - 东墙碰撞
│   └── WallWest (CollisionShape3D) - 西墙碰撞
├── VisualSystem (Node3D) - 可视系统（可替换）
│   ├── GroundMesh (MeshInstance3D) - 地面网格
│   ├── WallNorthMesh (MeshInstance3D) - 北墙网格（临时）
│   ├── WallSouthMesh (MeshInstance3D) - 南墙网格（临时）
│   ├── WallEastMesh (MeshInstance3D) - 东墙网格（临时）
│   └── WallWestMesh (MeshInstance3D) - 西墙网格（临时）
└── GameManager (Node3D) - 游戏管理器（按需创建骰子）
    └── [空] 骰子由游戏管理器动态创建，不预先放置
```

### 未来架构（美术资源替换后）
```
Node3D (主节点)
├── Camera3D (摄像机，由 CameraManager 管理)
├── DirectionalLight3D (光源)
├── BoundarySystem (StaticBody3D) - 碰撞边界系统（保持不变）
│   ├── Ground (CollisionShape3D) - 地面碰撞
│   ├── WallNorth (CollisionShape3D) - 北墙碰撞
│   ├── WallSouth (CollisionShape3D) - 南墙碰撞
│   ├── WallEast (CollisionShape3D) - 东墙碰撞
│   └── WallWest (CollisionShape3D) - 西墙碰撞
├── ArtScene (Node3D 或 PackedScene) - 美术场景（替换 VisualSystem）
│   └── 导入的完整美术资源（如城镇模型、建筑等）
└── GameManager (Node3D) - 游戏管理器
    └── [动态创建骰子] 按需创建，不预先放置
```

**架构说明**：
1. **BoundarySystem（碰撞边界系统）**：永久保留，负责游戏物理碰撞
2. **VisualSystem（可视系统）**：临时使用四面墙，后续替换为完整美术场景
3. **两者独立**：碰撞和可视分离，互不影响
4. **骰子完全独立**：场景中不预先放置任何骰子，由 GameManager 按需动态创建

### 阶段 4：骰子配置（动态创建）

**核心原则**：
- ✅ **场景中不预先放置任何骰子**
- ✅ **骰子完全由 GameManager 按需动态创建**
- ✅ **使用 DiceManager 或 GameManager 统一管理骰子实例**

**动态创建流程**：
```gdscript
# 在 GameManager 或场景脚本中
func create_dices_for_level(dice_type: String, count: int):
    var dices = []
    for i in range(count):
        var dice = DiceFactory.create_dice(dice_type)  # 工厂模式创建
        dices.append(dice)
    
    # 使用 DiceThrowController 自动布局
    DiceThrowController.apply_centered_layout(dices, 4.75, 2.0)
    
    return dices
```

**使用场景**：
- 战斗关卡：创建战斗用骰子（属性骰子或技能骰子）
- 奇遇关卡：创建随机事件骰子
- 交易关卡：创建交易用骰子
- 奖励关卡：创建奖励骰子

**优势**：
- 场景纯净，只包含场景本身元素
- 骰子按需创建，节省资源
- 灵活配置，不同关卡使用不同骰子组合
- 易于扩展，支持新的骰子类型

### 问题 1：墙体替代方案 ✅ 已确定架构

**用户问题**：如果后续使用导入的资源作为墙体，是否可以使用完整的地图而不是分成四个墙？

**解决方案**：采用**双层架构设计**
- **BoundarySystem（碰撞边界）**：永久保留，独立管理，负责物理碰撞
- **VisualSystem（可视系统）**：临时使用四面墙，后续整体替换为导入的美术场景
- **优势**：
  - 碰撞和可视完全分离
  - 美术资源替换不影响游戏逻辑
  - 可以导入完整的城镇/场景模型作为 VisualSystem
  - BoundarySystem 保持标准配置，确保游戏机制一致

### 问题 2：美术资源加载方式 ✅ 已确定方案

**用户问题**：导入后的美术资源是需要提前配置在场景中，还是依然通过动态加载？

**解决方案**：提供两种模式，默认使用**场景预配置**

**模式 A：场景预配置（推荐，默认）**
```gdscript
# 在场景文件中预先放置美术资源节点
Node3D (主节点)
├── BoundarySystem (碰撞边界)
├── ArtScene (PackedScene 实例)  # 预先配置好
└── DiceManager
```
- **优点**：加载快，编辑器可见，易于调试
- **缺点**：每个场景需要单独配置
- **适用**：固定场景，如三个关卡场景

**模式 B：运行时动态加载**
```gdscript
# 在场景脚本中动态加载美术资源
func _ready():
    var art_scene = load("res://art_scenes/village.tscn").instantiate()
    add_child(art_scene)
```
- **优点**：灵活，可根据条件加载不同资源
- **缺点**：加载时需要等待，调试复杂
- **适用**：需要动态切换的场景

**当前决定**：使用**模式 A（场景预配置）**
- 在模板场景中创建 VisualSystem 节点作为占位符
- 后续美术资源制作完成后，直接在编辑器中替换 VisualSystem 子节点
- 保持简单、直观、易于维护

## 📌 核心设计原则

1. **碰撞与可视分离**：BoundarySystem 永久保留，VisualSystem 可替换
2. **统一管理**：CameraManager 管理所有摄像机，DiceThrowController 管理所有投掷
3. **标准化**：所有场景使用相同的碰撞边界配置
4. **可扩展性**：支持未来美术资源替换
5. **易于维护**：场景预配置模式，编辑器可见，易于调试
6. **骰子独立**：**场景中不预先放置任何骰子，完全由 GameManager 按需创建**
